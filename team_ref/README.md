# team_ref/

팀원(용욱, 상혁, 경모, 규중)이 공유해준 코드/모델의 **read-only 참조본** 아카이브.

## 원칙

1. **절대 수정 금지** — 각 스냅샷은 받은 그 상태 그대로 유지. 개선하려면 `../src/`나 새 실험 폴더에 복사한 뒤 편집.
2. **버전 덮어쓰기 금지** — 새 버전이 오면 **새 폴더로 추가**. 이전 버전 삭제 X. 스코어 상승 요인을 diff로 추적할 수 있게.
3. **재현 검증 필수** — 스냅샷 받자마자 로컬에서 실행해 원본 저자의 결과(리더보드 점수 or test 예측)와 일치 확인 → `NOTES.md`에 "재현 OK" 기록.

## 폴더 이름 규칙

```
{저자}_v{버전}_lb{리더보드점수}/
```

예:
- `sanghyuk_v01_lb0.77585/` — 상혁이형 v1, 리더보드 0.77585
- `sanghyuk_v02_lb0.78XXX/` — 상혁이형 v2 (개선본)
- `kyungmo_aug_v01/` — 경모 데이터 증강 스크립트 v1 (리더보드 점수 없으면 생략)

리더보드에 오르지 않은 실험/유틸은 점수 태그 생략 가능 (`{저자}_{목적}_v{버전}/`).

## 각 스냅샷 안 구조

```
{name}/
├── NOTES.md            # 필수. 아래 템플릿 준수
├── (원본 파일 그대로)
└── ...
```

## `NOTES.md` 템플릿

```markdown
# {저자} v{버전} — LB {점수}

## 메타
- **받은 날짜**: YYYY-MM-DD
- **저자**: {이름}
- **원본 위치**: {SCP 경로 or 슬랙/카톡 링크}
- **리더보드 점수**: {점수 / 순위 / 제출일}

## 접근 요약
- 모델: (예: qwen2.5-1.5B-instruct → distilled from claude)
- 입력 스키마: (예: current_prompt + history 마지막 3턴 요약)
- 학습 데이터: (예: full train 70k / augmented / subset)
- 학습 방법: (예: LoRA, full FT, distillation loss 등)
- 추론: (예: batch 32, greedy, 14 클래스 softmax)

## 재현 방법
```bash
cd team_ref/{name}
pip install -r requirements.txt
python script.py  # or 별도 지시
```
- 재현 결과: (test 5샘플 예측이 원본과 일치 → OK)
- 재현 시 실측 리소스: (예: 3090 1장, 7분, 3.2GB VRAM)

## 파악한 핵심 아이디어
- (관찰 1)
- (관찰 2)

## 개선 여지 hypothesis
- (rare class 대응이 약해 보임 → 확인 필요)
- (history 활용 미약 → 추가 시 개선 여지?)
```

## `_incoming/`

SCP로 새 코드가 도착하면 여기에 임시로 놓임. 사용자가 정리 지시하면 규칙에 맞는 폴더로 옮기고 `_incoming/`은 비움.

## 팀원 → 사용자(김건우) 방향

이 폴더는 사용자가 팀원 코드를 **소화·재현·개선 아이디어 도출**하기 위한 공간. 사용자가 만든 개선안은 여기 넣지 않고 `../src/` + `../experiments/`에 관리. 팀 공유용 최종본은 별도 팀 저장소.
